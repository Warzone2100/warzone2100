# Multiplayer compatibility version

Warzone 2100 clients may join the same multiplayer game only when both fields of
the multiplayer compatibility version are equal. The host rejects a client with
a different value before it joins the game. The version is also recorded in
multiplayer replays so that a mismatch can be reported during playback.

The version is maintained in
[`lib/netplay/autorevision_netplay.cmake`](../lib/netplay/autorevision_netplay.cmake).
It is intentionally independent of release tags, branches, Git revisions, and
commit counts. The human-readable release version is still advertised in lobby
details, but it is not used by the connection compatibility check.

Increment the compatibility version before merging a change when any of these
conditions applies:

- the bytes exchanged between peers, their meaning, ordering, validation, or
  handshake behavior changes;
- deterministic simulation behavior changes, including RNG, game logic, timing,
  synchronization, or serialization that affects simulation state; or
- multiplayer-relevant data changes in a way that can alter simulation, map or
  game rules, validation, or synchronized state.

Do not increment it for rendering, audio, UI, localization, documentation,
build/packaging, release-version, or other changes that cannot affect
multiplayer interoperability or deterministic simulation.

Use `NETCODE_VERSION_MINOR` for each normal incompatible change. If it would
overflow its unsigned 32-bit value, increment `NETCODE_VERSION_MAJOR` and reset
the minor value to zero. Version `0.0` is reserved for lobby availability checks.

A point release must keep the existing compatibility version when its changes
do not meet one of the increment conditions above. For example, two point
releases that differ only in rendering fixes, translations, packaging, or
release metadata will advertise the same compatibility version and may connect.
Changing a release tag or creating additional commits is never by itself a
reason to increment the compatibility version.

The initial explicitly maintained major value is `0x5000`, which sorts after
all values generated by the previous metadata-based scheme. Clients using the
old scheme remain incompatible; once releases use the maintained version,
compatible point releases retain the same value.

Run the focused generation test with:

```sh
cmake --build <build-directory> --target test_netplay_compatibility_version
```
