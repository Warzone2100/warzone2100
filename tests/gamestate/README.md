# GameState fidelity tests

Scripts that check whether a game restored from a GameState snapshot continues exactly like the game that wrote it.
They compare the per-tick sync CRC (`--gamestate-crc-trace`),
which is the same `syncDebug()` CRC multiplayer uses to detect a desync,
so "identical" means the restored game simulated exactly what the original did.

All of them need a built `warzone2100` binary, and most run headless.
Results go to `$OUT` (default `/tmp/gamestate-forkcrc`).

| Script | What it checks |
|---|---|
| `forkcrc.sh <bin> <test> <save tick> <end tick> [--dying \| --dying-filter <filter>] [--no-loaded] [--before-messages]` | **Fork test.** Run A starts a game, saves at the save tick (with `--dying`, at the first tick from there that ends with objects pending destruction) and keeps running, and run B loads that save in a fresh process. The traces are compared after the save tick. On a difference, both runs are repeated with the full sync-debug log of the first differing tick and the first differing lines are printed. A game message read between the save and the next tick (which the save missed) also fails the cell. `--before-messages` saves before the messages for the next tick instead. |
| `forkcrc.sh <bin> <test> <tick> <end tick> --rewind <k>` | **Rewind test.** Snapshots in-process at the tick, keeps running `k` more ticks, restores the snapshot in-process and keeps running, and is compared with an uninterrupted run. If the two runs already differ before the snapshot (ex. a different `SEED`), the ticks the rewound run simulated twice are compared with each other instead. |
| `doublesave.sh <bin> <save> [--no-loaded]` | **Double-save test.** Loads a save and saves it again right after the load (before the first tick), and compares the two GameState documents section by section. |
| `betweenticks.sh <bin>` | **Between-ticks save test.** A fork cell saved between two ticks, right after a message processed there raised a player's sensor ranges (a test mod's `eventSyncRequest` handler), so tile coverage changes are still pending at the save. |
| `rewindfault.sh <bin> <test> <tick> <end tick> <k> <fault>` | **Rewind fault test.** A rewind test whose snapshot is damaged right before it is restored (`--gamestate-rewind-fault`), compared with an uninterrupted run: the restore is rejected before it changes anything and the live game goes on (the run must be IDENTICAL to the reference), or it restores anyway (shows unresolved references and compares the ticks after the snapshot), or it fails after changing live state (shows the stage, the exit status, the last tick and the assertions after the failure). |
| `replayrewind.sh <bin> <test> <tick> <end tick> <k>` | **Replay rewind test.** Records a headless skirmish game, plays its replay back (`--loadreplay`), and plays it back again with an in-process rewind. Both playbacks must reproduce the recording's CRCs (the rewound one after the snapshot), and the rewound playback must run on to the replay's end and quit with status 0. With `FAULT=replay-position` or `FAULT=no-replay-positions`, the snapshot's replay read positions are damaged and the restore must be rejected (the playback must then match the recording throughout). |
| `replayseek.sh <bin> <test> <end tick> <ring> [<seeks>]` | **Replay seek test.** Plays the recorded replay (shared with `replayrewind.sh`) back to its end with the snapshot ring (`--gamestate-snapshot-ring`, or `off`) and replay seeks (`--gamestate-seek-test`). Each seek must reach its target (or be replaced by the next), the playback must reach the replay's end and quit with status 0 with no sync error, and every tick's CRC (the last time it was simulated) must be the recording's. Prints the ring's statistics (snapshots kept and thinned out, compressed size, main-thread and worker time per snapshot) and each seek's timing. Without seeks it checks that the ring alone changes nothing. With `FAULT=<kind>[,<restores>]` (`--gamestate-seek-fault`) the first restores are damaged, and `EXPECT=older` or `EXPECT=restart` says which fallback must have been taken: an older snapshot, or playing the replay again from the start. |
| `guistress.sh <bin> replay <test> <end tick> <ring> <seeks> <stress>`<br>`guistress.sh <bin> skirmish <test> <end tick> <stress>` | **GUI test of the UI's references to game objects**, under `xvfb-run`. With `--gamestate-ui-stress`, the UI is pointed every few ticks at the droid most likely to die next, and every frame the game checks that no UI reference is to a freed object. Replay mode: records the game (fresh each run, since a replay from another build opens a version warning that waits for a click), and plays it back with the GUI, the ring and the seeks. Every seek must reach its target and every tick's CRC must be the recording's. Skirmish mode: plays the game with the GUI with and without the stress. The two must be IDENTICAL, and the one without must be IDENTICAL to the same game played headless. Both: no frame may find a reference to a freed object. |
| `replaycontrols.sh <bin> [<test> [<end tick>]]` | **GUI test of the replay controls** (`src/hci/replay_controller.h`), under Xvfb, with `xdotool`. Records a headless skirmish game (fresh each run), plays its replay back with the GUI (the snapshot ring runs by default), and drives the transport bar with the mouse: a click near the timeline's end (a seek forward to the replay's end), pause and "back 15 seconds" from the end (a restore, after which playback must stay paused), play and "back to the start", a long seek stopped with Esc, and a click at a third. Each seek must be requested at the time clicked and reach its target, and every tick's CRC (the last time it was simulated) must be the recording's. The click positions follow the bar's layout at 1280x800. |
| `matrix.sh <bin> [filter]` | Runs the standard set of fork, rewind and double-save cells. |
| `camtransition.sh <bin>` | **Campaign transition test.** Plays `CAM_2A` into the off-world mission `SUB_2_1` and back out without a player (a test mod built from the campaign scripts calls `camNextLevel`), twice, and checks that no assertion fires and that both runs start every level at the same `gameTime` with the same power and trace the same CRCs (no tick runs between a `loadLevel` and the next level). Covers what has to be rebuilt or dropped when worlds are freed and swapped between ticks. The matrix also runs fork cells and a double save through this level change, with its test mod (`EXTRA=--mod=camtransition.wz`, which `forkcrc.sh` and `doublesave.sh` pass to the game). |
| `camlaunch.sh <bin>` | **Campaign transporter launch test.** Launches the player's transporter from `CAM_2A`'s home base as the launch button does, twice: once in a pre-off-world level, whose exit loads the off-world mission `SUB_2_1` (the home world, which the level change keeps, must keep no coverage of the transporter), and once with `CAM_2A`'s own conditions, where the transporter stays. Checks the tile coverage of both worlds every tick. |
| `camreinforce.sh <bin> [<reinforce tick> <save tick> <end tick>]` | **Campaign reinforcement test.** A test mod sends the player's transporter from `CAM_2A` into the off-world mission `SUB_2_1` and gives it reinforcements every 30 s. At `<reinforce tick>` (default 33000), `--gamestate-test-reinforce` sends reinforcements as the transporter screen does. They must start flying in (`eventTransporterArrived`) 10 s before the 30 s are up, at the same tick headless, after a save and load while they wait (a `forkcrc.sh` cell saved at `<save tick>`, default 45000), and with the GUI (`xvfb-run`, if installed, and the run must also be IDENTICAL to the headless one). |
| `camtextures.sh <bin>` | **Replaced textures across campaign level changes** (with the GUI under `Xvfb`: a headless game doesn't load the models' textures). A test mod plays `CAM_2A`, replaces the scavengers' texture again at 2 s (the rules replaced it when the level started), and goes on without a player: `SUB_2_1` (off-world), `CAM_2B` (home), `CAM_3A` (another data set, whose models load the original texture again). Run A saves at 10000, and run B loads that save and plays the same levels. Every level start after the save must show the same replaced textures (`--gamestate-test-continue-levels` logs them) as in run A. Run B also saves on `CAM_3A`, and loading that save and saving it again keeps the same replacements. |
| `deadgrid.sh <bin>` | **Dead grid readers test.** Runs the `dead_grid` movement bench scenario, in which objects die in a tick where a grid reader that runs later in that tick would find them (the grid keeps them until the end of the tick): a second squish of a dead person, a truck picking a dead structure to repair or help build, a dead droid in the way of a new structure, and a dead droid keeping a gate open. Checks the scenario's `deadgrid:` lines and that no dead action target asserts. The matrix also saves this scenario at the ticks of those deaths. |
| `cmptrace.py`, `difflog.py`, `cmpsave.py` | The comparison helpers used by the scripts (`cmptrace.py --replayed <trace>` compares a rewound run with itself). |

`<test>` is a `--skirmish` settings file from `data/mp/tests` (ex. `highground`, `miza`), which runs bundled AIs,
or `mb:<scenario>` for a movement bench scenario (ex. `mb:perf_battle`),
which runs without AI scripts and so isolates engine restore fidelity,
or `cam:<start level>` for a campaign (`--game`, ex. `cam:CAM_2A`).
`CAM_1A` pauses on a guide topic, and a level can end early when nobody plays it, so keep end ticks short.

`mb:gamestate_deaths` is a scenario for these tests:
every few seconds it kills, in one tick, several droids (some while being repaired), a commander,
a repair facility while it repairs, a wall and an oil drum, and its `eventDestroyed` handler removes one more droid.
`mb:gamestate_rewind` changes script state after a rewind snapshot that an in-process restore must roll back
(a new global, `groupSizes[]` of a group filled later, a declared global, a group member, a timer).
`mb:gamestate_scripts` is another: it saves while some members of a script group are aboard a transporter
(which drops them after the save),
and with object labels armed for one player only (`resetLabel(label, player)`) on objects first seen after the save.
A group member missing after a load, or an `eventObjectSeen` the original game did not have, spawns a droid.
`gamestate_cobra` and `gamestate_bonecrusher` are `miza` with every slot running Cobra or BoneCrusher
(`miza` itself runs SemperFi, NullBot and the default AI, Nexus), so that the matrix covers every bundled AI.

Options passed to the game (all inert unless given).
They are developer options: `--help` doesn't list them, and their descriptions aren't translated.

| Option | Effect |
|---|---|
| `--gamestate-save-at-tick=<tick>:<path>` | Write a savegame at the first tick >= tick, and keep running. It is written at the save point, like a menu save: between two ticks, once the game loop has processed every message for the next tick (`src/gamestate_capture.h`). |
| `--gamestate-save-when-dying` | Delay that save (and the rewind snapshot) until a tick that ends with objects pending destruction. |
| `--gamestate-dying-filter=<filter>` | What those objects must include: comma-separated, a minimum count, `droid`, `structure`, `feature`, `pendingvis` (an object whose tile visibility removal is still pending). |
| `--gamestate-exit-at-tick=<tick>` | Quit at the first tick >= tick. |
| `--gamestate-rewind-test=<tick>:<k>` | Snapshot in-process at the tick, restore it in-process `k` ticks later. Logs the snapshot and restore times. |
| `--gamestate-rewind-fault=<kind>[,continue]` | Damage the rewind snapshot right before the restore: `truncate`, `section-version:<section>`, `bad-stat`, `duplicate-id`, `dangling-ref`, `overlap`, `edge`, `off-map`, `over-limit`, `throw-at:<stage>` (a throw when the restore reaches that stage: `teardown`, `terrain`, `globals`, `formations`, `worlds`, `dying`, `pass1`, `pass2`, `post`, `sections`, `scripting`, `derived`, `counters`), or, during replay playback, `replay-position` (a game queue's replay read position past the replay's end) or `no-replay-positions` (the snapshot's replay read positions dropped). A restore that fails before changing live state lets the live game go on, and a later failure quits (or with `,continue`, ticks the half-restored game on). `rewindfault.sh`. |
| `--gamestate-snapshot-ring=<interval ms>[,<budget KB>[,<zlib level>]][,sync]` or `=off` | The snapshot ring (`src/gamestate_snapshot_ring.h`) during replay playback. With options, it runs during every playback, headless too, from the first capture point (a snapshot every `<interval>` of game time, captured on the main thread and checked, written out, compressed and stored by a worker thread). Above the budget (default 64 MB), older snapshots are thinned out evenly. `sync` waits for the worker rather than taking a snapshot late, so the snapshots are taken at the same game times in every run (test-only). `off` turns it off. Without the option it runs during playback with the GUI only, every 30 s. Logs each snapshot taken, and statistics when it stops. `replayseek.sh`. |
| `--gamestate-seek-test=<at>:<target>[,<at>:<target>...]` | During replay playback: at the first capture point at or after each `<at>`, in order, seek to `<target>` (`src/gamestate_replay_seek.h`: restore the newest ring snapshot at or before it when needed, falling back to older ones and then to playing the replay again from the start, then fast-forward). Logs the restores and when the target is reached, with timings. `replayseek.sh`. |
| `--gamestate-seek-fault=<kind>[,<restores>]` | Damage the snapshots the replay seeks restore, the first `<restores>` of them in the run (default 1), with a `--gamestate-rewind-fault` kind, to exercise the seek's fallbacks. `replayseek.sh` (`FAULT`). |
| `--gamestate-test-reinforce=<tick>` | At the first capture point at or after `<tick>`, during an off-world campaign mission, send reinforcements as the player does from the transporter screen: a home base droid is put aboard the transporter waiting there, and it is launched. Not in a game loaded at or after `<tick>`. `camreinforce.sh`. |
| `--gamestate-test-continue-levels` | Go on to the next campaign level without the mission result screen (which waits for a click), and log the texture pages `replaceTexture()` replaced when each level starts and when a save is loaded. `camtextures.sh`. |
| `--gamestate-ui-stress=<ticks>` | Every `<ticks>` ticks (at the capture point), point the UI at the live droid with the fewest body points, whoever's it is: the camera tracks it, the sensor view targets it, it and its player's four next weakest droids are selected, and when it is the local player's, the build, manufacture, research, commander or order form is opened (or they are closed), in turn. Every frame, after the interface's refresh, check that every UI reference to a game object is to one not yet freed (`checkUiObjectRefs`, `src/uiobjectrefs.h`), and log the frames that find one. `guistress.sh`. |
| `--gamestate-resave-on-load=<path>` | After a GameState load has completed, save again before the first tick, and quit. |
| `--gamestate-test-seed=<seed>` | Make a run repeatable in another process, on any platform, with or without the GUI. A new game's random seed is `<seed>` itself (skirmish and multiplayer games in `SendFireUp`, campaign games when they start from the title loop or `--game`, but the movement bench keeps its own), logged as "Game random seed". Every script's `Math.random()` is seeded from `<seed>`, the player and the script name, and the scripts' `Date` is fixed to a time derived from it. The network latency is negotiated without the wall clock. `forkcrc.sh` passes `$SEED` (default 1). |
| `--gamestate-save-before-messages` | Take the `--gamestate-save-at-tick` save and the rewind snapshot right after a tick, before the game loop processes the messages for the next tick, instead of at the save point. A game saved there can resume differently. `forkcrc.sh --before-messages`. (`--gamestate-save-after-messages`, which selects the default save point, is also accepted, as is `forkcrc.sh --after-messages`.) |
| `--gamestate-save-when-coverage-pending` | Delay that save until tile coverage changes are pending (ex. a range upgrade between ticks). `forkcrc.sh --coverage-pending`. |
| `--gamestate-check-coverage=<ticks>` | Every `<ticks>` ticks, right before a harness save or rewind snapshot, and right after a GameState load, check in both worlds that every droid's and structure's tile coverage matches a recompute from its current state, that the per-tile counts add up to the watched tiles, and that watched tiles are explored for every player sharing vision, and log the checks that differ. A loaded game can only recompute it. `forkcrc.sh` passes `$CHECK_COVERAGE` (default 0, off, but `matrix.sh` sets 10), and a difference fails the cell. |
| `--gamestate-test-suppress-loaded-event` | On a GameState load, don't fire `eventGameLoaded` and drop the queued `eventResearched` replay. Separates engine restore fidelity from what load-time script handlers do. Only changes anything for a save without the interface the scripts set up (its `localState` interface block and presentation version 2), since a save that has it is loaded without `eventGameLoaded` anyway. |

Reading the results:

- A tick whose CRC differs is echoed a few ticks later in the `GAME_GAME_TIME` message,
  so one difference repeats at a fixed stride for the rest of the run.
  `cmptrace.py` reports "echo chain only" when that is all that differs,
  and otherwise the first tick that is not an echo (where the simulation itself parts).
  When consecutive ticks differ, the simulation has parted at the first one.
- Movement bench saves are loaded with the standard rules script rather than the bench's own,
  and fork cells that use bundled AIs also measure what the AI scripts restore (see the `var` convention).
  Use the `mb:` cells to isolate the engine.
- A save that has the interface the scripts set up is loaded without `eventGameLoaded`,
  so `--no-loaded` only matters for saves without it.
